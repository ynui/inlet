01

Use inlet

Install the client, create a token, and give your local app a public URL. The public demo supports GitHub login and open signup.

Install the client

On macOS or Linux, install with Homebrew. The package includes the client, server, and admin CLI.

brew install ynui/tap/inlet

Or download an archive for your OS and CPU. Extract it and put `inlet` on your PATH.

Download a release ↗Install notes ↗

Create a token and start a tunnel

Start your app first. Replace 3000 with the port your app listens on.

inlet login
inlet http 3000

Use inlet login to link device tokens to GitHub; it opens a browser for approval, then returns to the terminal and saves an inlet token and server URL locally. Or use inlet signup for an open token managed under the server’s per-IP limit. The client prints the public link; share it to let someone reach your app. Press Ctrl-C to stop the tunnel. Your GitHub access token is not saved by inlet.

Using a private inlet server? Ask its operator for an invite, then run inlet signup --server https://inlet.example.com --invite <invite-code>. The URL is saved with your token; `https://` is converted to the secure WebSocket connection automatically.

Client commands

inlet config showShow the saved server, token status, and inspector port.
inlet config set-server https://inlet.example.comSwitch servers. Use `https://` for a TLS site or `http://localhost:8080` for local development.
inlet versionShow the installed client version.
inlet doctor --port 3000Check the configured inlet server and, optionally, your local app.
inlet auth <token>Save a client token supplied by the server operator.
inlet login [--server URL] [--label NAME] [--no-browser]Sign in with GitHub and create an account-linked token for this client.
inlet token listSee and manage tokens for your GitHub account.
inlet token label <12-char-prefix> "work laptop"Name a token so it is easier to recognize in the list.
inlet token revoke <12-char-prefix>Revoke a token. It cannot open new connections after revocation.
inlet http 3000 --new-urlRotate the tunnel ID and get a new public link.
inlet http 3000 --inspect 4041Choose another local inspector port. The default is 4040.
The inspector at http://127.0.0.1:4040 shows recent request details and is only available on your machine. Inlet forwards HTTP; WebSocket upgrades from your public app URL are not supported.
02

Self-host inlet

Run one server behind your domain and TLS proxy. Clients and public requests share one inlet port.

1. Prepare the server

Point a DNS name such as inlet.example.com at your server. Install Docker with the Compose plugin, then clone inlet and set the public URL in its environment file.

git clone https://github.com/ynui/inlet.git
cd inlet
cp .env.example .env
# Edit .env:
# INLET_PUBLIC_BASE=https://inlet.example.com
# INLET_OPEN_SIGNUP=false
# INLET_ADMIN_TOKEN=<long-random-secret>
# INLET_GITHUB_CLIENT_ID=<oauth-app-client-id>
# INLET_GITHUB_CLIENT_SECRET=<oauth-app-secret>

docker compose up -d --build
docker compose ps
docker compose logs -f inletd

Set INLET_PUBLIC_BASE to the HTTPS address users will open. To offer GitHub login, create a GitHub OAuth App, enable Device Flow, and set both GitHub credentials. Set INLET_OPEN_SIGNUP=true to allow new accounts; existing accounts can add client tokens when it is off. Otherwise, keep signup invite-only. Create a strong admin secret with openssl rand -hex 32, then put its output in INLET_ADMIN_TOKEN.

Keep the database. Compose stores it in ./data/inlet.db. Back up that directory; it contains token and invite records. Keep `.env` private and out of Git.

Prefer building from source? Install Go 1.23+, clone the repository, then run make build and start ./inletd. Put server settings in .env or export the matching INLET_* variables before starting it.

2. Put HTTPS in front

Terminate TLS at Nginx and forward every path to inlet's listener. Add the map once inside Nginx's http block; put the server block in your site config. Replace the hostname, certificate paths, and upstream for your deployment.

map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name inlet.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
    }
}
If Nginx is on the host, set its upstream to the published inlet port and restrict direct access to that port with your firewall. If Nginx shares inlet's Compose network, use proxy_pass http://inletd:8080; and remove the host ports mapping. Inlet needs WebSocket upgrade headers for its client control connection.

3. Invite clients and administer the server

With INLET_ADMIN_TOKEN set and the server running, install the inlet package on your workstation and connect the separate admin CLI.

brew install ynui/tap/inlet
inlet-admin auth --server https://inlet.example.com <admin-token>
inlet-admin invite create --ttl 24h --label teammate
inlet-admin token list --limit 50 --offset 0

Send the one-time invite code to the client. They claim it with inlet signup --server https://inlet.example.com --invite <invite-code>; the client saves the token and server URL.

Remote administration uses HTTPS and a separate inlet-admin token. The bootstrap token appears as admin-token in token lists. Never share it with regular clients.

Admin commands

inlet-admin config showShow the configured server and whether an admin token is saved.
inlet-admin config set-server https://inlet.example.comChange the remote server used by the admin CLI.
inlet-admin config set open-signup falseEnable or disable open signup remotely.
inlet-admin invite create --ttl 24h --label NAMECreate a single-use invite and copy its code before closing the terminal.
inlet-admin token list --limit 50 --offset 50View token metadata in pages. Offset skips that many rows; maximum page size is 200.
inlet-admin token create --label NAMECreate a client token directly. Its secret is shown only once.
inlet-admin token create --label NAME --adminCreate another administrator credential; protect it like the bootstrap secret.
inlet-admin token label <12-char-prefix> "NAME"Rename a token shown by `token list`.
inlet-admin token revoke <prefix> [<prefix> ...]Revoke one or more token prefixes, up to 100 per command.
inlet-admin versionShow the installed admin CLI version.

Local server commands

Run these inside the server container or from the directory containing its database. With Docker Compose, prefix each command with docker compose exec inletd.

inletd doctorCheck the running server health endpoint.
inletd invite create --ttl 24h --label NAMECreate a one-time invite for a client.
inletd token listList token prefixes, labels, tunnel IDs, and state.
inletd token revoke <prefix>Revoke a token from the server database.

Operate and troubleshoot

docker compose ps
docker compose logs -f inletd
docker compose exec inletd inletd doctor
docker compose exec inletd inletd invite create --ttl 24h --label teammate
docker compose exec inletd inletd token list
docker compose down

To update, pull the latest source and run docker compose up -d --build. To back up the database safely, stop inlet, archive data/, then start it again. For configuration options and the full proxy example, see the deployment guide.
